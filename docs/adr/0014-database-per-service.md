# ADR-0014. Один PostgreSQL, база и роль на сервис

**Статус:** принято, 02.09.2026

## Контекст

Каждый сервис должен владеть своими данными. Требуется способ обеспечить изоляцию,
не превращая локальный стенд в неподъёмный.

## Решение

Один инстанс PostgreSQL, в нём отдельная база и отдельный пользователь на каждый
сервис, владеющий данными: `auth`, `catalog`, `booking`, `notification`.
Права выданы только на свою базу. `api-gateway` базы не имеет.

## Альтернативы

**Отдельный инстанс PostgreSQL на сервис.** Каноничнее и ближе к продакшену:
независимое масштабирование, независимые сбои. Но вчетверо больше подов и памяти
на локальном кластере при нулевой учебной разнице.

**Одна база, схема на сервис.** Компактнее всего, но соблазн сделать кросс-схемный
джойн слишком велик, и однажды он будет сделан — после чего сервисы перестанут быть
независимыми незаметно для всех.

## Последствия

- Кросс-сервисный джойн физически невозможен: у пользователя нет прав на чужую базу
- Локальный стенд остаётся подъёмным
- Инстанс — общая точка отказа; для учебного проекта приемлемо, в продакшене
  разносится без изменения кода приложения
- Миграции независимы: у каждого сервиса своя история Alembic
