# ADR-0009. Собственный api-gateway на FastAPI

**Статус:** принято, 02.09.2026; пересмотрено 17.10.2026 — маршрутизация и Ingress

## Контекст

Нужна единая точка входа: проверка токена, ограничение частоты запросов,
сквозной идентификатор запроса, маршрутизация в пять сервисов.

## Решение

Собственный `api-gateway` на FastAPI. Отвечает за:

- проверку подписи JWT через JWKS и проброс `X-User-Id` / `X-Roles`;
- rate limiting (sliding window в Redis) с разными лимитами для анонимов,
  авторизованных и дорогих операций;
- генерацию и проброс `X-Correlation-Id`;
- проксирование по первому сегменту пути;
- сводный OpenAPI.

Гейтвей остаётся тонким. Единственное исключение — агрегирующий эндпоинт
`GET /api/v1/masters/{id}/card`, склеивающий профиль из `catalog` и ближайшие
слоты из `booking`: он существует, чтобы паттерн BFF был реализован явно,
но не расползался.

Снаружи стоит k8s Ingress, который занимается только TLS и маршрутизацией на гейтвей.

## Альтернативы

**Только ingress-nginx, каждый сервис проверяет JWT сам.** Меньше кода и на один
сетевой хоп меньше, но нет единой точки для лимитов по `user_id` и по типу операции,
нет агрегации и нет единого места генерации correlation-id.

**Kong или Traefik с плагинами.** Продакшн-путь, конфигурация вместо кода.
Но механика rate limiting и проверки токенов осталась бы непрожитой.

## Последствия

- Плюс один сетевой хоп на каждый запрос
- Гейтвей — критичный компонент: 2 реплики и HPA обязательны
- Есть соблазн наращивать в гейтвее доменную логику; ограничение «один
  агрегирующий эндпоинт» зафиксировано явно, чтобы этого не произошло

## Пересмотр (17.10.2026)

**Что изменилось.**

- Маршрутизация не «по первому сегменту пути», а по таблице шаблонов, которая
  читается сверху вниз (`barber_gateway/routing.py`, `e440888`): `/masters/{id}/schedule`
  и `/masters/{id}/settings` — `booking`, остальное под `/masters` — `catalog`.
  Ошибка документа: мастер с самого начала делился между двумя сервисами
  ([ADR-0017](0017-master-services-in-catalog.md)), и первый сегмент его не различает.
- Ingress — Traefik в `kind`, TLS не настроен: стенд локальный, хост `barber.local`
  по HTTP. ingress-nginx не используется — проект закрыт в марте 2026.
- Гейтвей не ретраит проксируемые запросы и держит предохранитель на каждый сервис;
  размыкает его только отсутствие ответа. Rate limiter при недоступном Redis
  пропускает запросы и делит с кэшем предохранитель к Redis (`a20682a`).

Решение «свой тонкий гейтвей на FastAPI» не изменилось.
