# Документация проекта

Микросервисная платформа онлайн-записи клиентов к парикмахерам.
Учебный проект, доводится до полностью рабочего состояния.

**Стек:** Python 3.12+, FastAPI, SQLAlchemy 2.x (async), PostgreSQL, Redis, Kafka,
Kubernetes, OpenTelemetry, Prometheus, Grafana, Tempo, Loki.

**Статус архитектуры:** принята 02.09.2026. Версия 1. Сверена с реализацией
17.10.2026 — расхождения в [17-design-vs-reality.md](17-design-vs-reality.md).

## Три вещи, которые определяют всю систему

1. **Границы сервисов проведены по транзакционной согласованности.** Всё, что должно
   меняться атомарно, лежит в одном сервисе и в одной базе. Поэтому расписание и брони
   в одном сервисе `booking`, а не в двух — см. [ADR-0001](adr/0001-merge-scheduling-into-booking.md).
2. **Единственный арбитр занятости мастера — ограничение PostgreSQL.** Ни кэш, ни
   распределённая блокировка, ни проверка в коде — см. [ADR-0002](adr/0002-exclude-constraint-as-arbiter.md).
3. **Саги в системе нет, и это результат, а не упущение.** Ни одна бизнес-операция
   не пересекает границу сервиса транзакционно — см. [ADR-0003](adr/0003-no-saga.md).
